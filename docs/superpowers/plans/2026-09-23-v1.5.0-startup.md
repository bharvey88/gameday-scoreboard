# Startup Only (v1.5.0) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Get a panel from power-on to its first real scoreboard faster, with the boot screen covering the wait (10 s cap) and no "----" or "Loading" board at boot or on a team change.

**Architecture:** Four changes taken from PR #17 and rebuilt on top of v1.4.5 (PRs #14 and #16): the fetch loop's readiness poll drops from 5 s to 500 ms; the team endpoint's answer is kept in flash so a boot within a day skips that read; the gameday component announces the first real board (`board_ready`) and a team change (`board_pending`); and #14's boot overlay (`firmware/pages/boot.yaml`) holds on a "Getting scores" view until `board_ready`, never longer than 10 s after the hide was asked for. The two decisions that can be unit tested (is the cache still good, is the hold still on) live in a new pure header, `components/gameday/startup.h`, with host tests.

**Tech Stack:** ESPHome 2026.8.2 (venv at `~/development/tools/esphome-venv`), LVGL, C++17, ArduinoJson 7.4.3, host tests via `make -C tests`.

## How the boot screen hold works

```
                        boot_hide asked for (connect timer, team_picked,
                        45 s fresh-panel timer, boot button's 20 s, board_pending)
                                          |
                     not on Wi-Fi? ------ yes ----> unchanged: keep the Wi-Fi lost /
                                          |         setup lines up (#14 behavior)
                                          no
                                          |
             boot_hold_since_ms == 0 and !board_ready()  ->  boot_hold_since_ms = now
                                          |
                     gameday_ctl.boot_hold(since) ?  (startup.h: !board_ready and
                                          |            now - since < 10 s)
                        yes --------------+------------- no
                         |                                |
          overlay up, "Getting scores",          boot_hold_since_ms = 0,
          bar moving, boot_check running         overlay hidden (#14 behavior)
                         |
        board_ready action (gameday-common.yaml) or boot_refresh's 500 ms tick
        sees the hold end  ->  boot_hide again  ->  "no" branch
```

- A configured panel with "Show address at boot" off asks for the hide the
  moment it joins Wi-Fi, so the cap is 10 s after Wi-Fi. With the setting on,
  the address shows for 3 s first, then the hold (cap 10 s after that).
- A fresh panel keeps #14's QR screen until a team is picked or 45 s pass.
  Picking a team clears `board_ready`, so `team_picked` lands in the hold.
- A team change on a configured panel fires `board_pending`, which starts a
  new hold: the new team's scores load behind "Getting scores".
- When the cap runs out the overlay hides over whatever the board has. That
  is never "----" or "Loading" any more (Tasks 6 and 8).
- The boot button keeps priority: `board_ready` does not hide the overlay
  while the button's 20 s address or the reset warning is up.

```cpp
// Startup helpers: the saved team info a boot can start from, and how long
// the boot screen waits for the first scoreboard. Pure, with no ESPHome
// includes, so the host tests compile it directly.
#pragma once

#include <cstdint>
#include <cstring>
#include <string>

#include "espn_parse.h"

namespace espn {

// The team endpoint's answer for the saved team, kept in flash so a boot can
// go straight to the scoreboard instead of reading the team endpoint (about
// 23 KB) first. Only what the scoreboard request needs.
struct TeamCache {
  uint8_t league;
  uint32_t team_id;
  char event_id[16];
  int64_t kickoff_epoch;
  uint32_t group;
  int64_t saved_epoch;
} __attribute__((packed));

// Older than this, the team endpoint is read again first.
static const int64_t TEAM_CACHE_MAX_AGE = 24 * 3600;
// A cached game that kicked off longer ago than this is over: read again.
static const int64_t TEAM_CACHE_GAME_OVER = 4 * 3600;

// Fills `out` from the schedule just read for this team. False when there is
// nothing worth keeping: no next game, or an event id too long for the record.
inline bool team_cache_save(const Schedule &s, League league, uint32_t team_id, int64_t now_epoch,
                            TeamCache &out) {
  if (!s.valid || s.event_id.empty() || s.event_id.size() >= sizeof(out.event_id) || now_epoch <= 0)
    return false;
  out = TeamCache{};
  out.league = (uint8_t) league;
  out.team_id = team_id;
  memcpy(out.event_id, s.event_id.c_str(), s.event_id.size());
  out.kickoff_epoch = s.kickoff_epoch;
  out.group = s.group;
  out.saved_epoch = now_epoch;
  return true;
}

// The cached schedule, only while it can still be right: the same team,
// saved in the last day, and a game that has not been over for hours.
inline bool team_cache_load(const TeamCache &c, League league, uint32_t team_id, int64_t now_epoch,
                            Schedule &out) {
  char id[sizeof(c.event_id) + 1];
  memcpy(id, c.event_id, sizeof(c.event_id));
  id[sizeof(c.event_id)] = '\0';
  if (c.league != (uint8_t) league || c.team_id != team_id || id[0] == '\0')
    return false;
  int64_t age = now_epoch - c.saved_epoch;
  if (age < 0 || age > TEAM_CACHE_MAX_AGE)
    return false;

                      id: boot_overlay
                      hidden: true
```
